# Day6 模型调用与聊天接口说明

## 今天完成了什么

Day6 的目标是让项目具备第一次模型对话能力。

本次已完成：

1. 新增 `ChatRequest` 和 `ChatResponse` schema
2. 新增 `ChatService` 作为模型调用服务层
3. 新增 `POST /api/v1/chat` 接口
4. 扩展配置文件，加入模型调用相关环境变量
5. 更新 `.env.example`，提供本地配置模板

## 为什么要先做 chat 接口

Day6 先做 `/chat`，是因为它是后面 RAG 和 Agent 的共同基础。

后面无论你做：

1. RAG 问答
2. Agent 工具调用
3. 结构化输出
4. 流式返回

底层都离不开一次模型调用能力。

## 当前设计思路

当前 `/api/v1/chat` 采用三层结构：

1. 路由层：接收请求并返回响应
2. schema 层：约束输入输出结构
3. service 层：封装模型 API 调用逻辑

这样做的好处是，后面你要改模型提供商、加重试、加日志、加流式输出时，不用把逻辑写死在路由里。

## 当前接口说明

- 方法：`POST`
- 路径：`/api/v1/chat`

请求体示例：

```json
{
  "message": "请介绍一下金融知识库RAG系统",
  "system_prompt": "你是一名严谨的金融AI助手。"
}
```

## 当前可能的报错

你现在最常见的一个报错会是：

- `LLM_API_KEY_MISSING`

这是正常的，因为 Day6 先把能力接上，再由你填写真实模型配置。
